# MLCC 开发计划

## 本阶段：数据与扩展框架

- 独立 `freppledb.mlcc` 应用和官方属性扩展机制；
- 10 个行业数据模型及数据库迁移；
- 后台编辑、列表、菜单、REST API；
- 五工序幂等演示数据；
- 模型/API/迁移/校验/演示数据测试；
- 中文界面词条和架构文档。

本阶段明确不实现 OR-Tools 求解、不改写 frePPLe 核心规划引擎、不承诺生产级优化结果。

## 下一阶段：数据治理与求解输入

1. 与 MES/ERP 确认批次、配方版本、设备状态和质量冻结的权威来源。
2. 增加单位、精度、时间区和编码字典治理。
3. 设计排程快照，冻结一次运行的输入版本，避免运行中主数据漂移。
4. 增加配方生效期、设备维护窗、同炉规则覆盖率及谱系完整性检查。
5. 建立大规模数据性能基线和 API 幂等键。

## 求解器阶段

1. 将 `MlccScheduleRun` 定义为求解任务边界，异步导出不可变输入。
2. 以 CP-SAT/OR-Tools 建模设备选择、工序前后关系、炉次容量、同炉兼容、换型和交期。
3. 将可行解写回 `MlccScheduleResult`/`MlccFurnaceLoad`，保留目标值、约束违例和求解日志。
4. 支持取消、超时、重跑、方案比较与人工锁定。
5. 在影子模式验证后，才允许把结果转换为 frePPLe 制造订单日期和资源分配。

## 上线门槛

- 数据字典和接口契约经业务确认；
- 迁移可回滚，演示和生产数据严格隔离；
- 单元、集成、容量、并发和权限测试通过；
- 求解不可行、超时、部分结果和质量冻结均有可解释处理；
- 监控覆盖任务耗时、失败率、数据新鲜度和排程稳定性。
